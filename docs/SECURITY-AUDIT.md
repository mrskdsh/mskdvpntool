# Аудит безопасности

Проверка кода панели вручную по списку: вход и сессии, права, инъекции, секреты, зависимости, установка.
Автотесты безопасности: `tests/test-security.sh` (37 проверок).

## Важно: границы проверки

Это ручной разбор кода плюс автотесты, а не внешний тест на проникновение. Гарантировать «уязвимостей нет» нельзя. Не проверялись на настоящем железе: поведение за реальным Caddy/Cloudflare (какой IP видит панель), настройки хостера и firewall, сами приложения-клиенты. Раздел D чек-листа закрывает часть этого. Перед тем как брать клиентов за деньги, имеет смысл дать панель на проверку второму специалисту.

## Найдено и исправлено

| Что | Чем было опасно | Как исправлено |
|---|---|---|
| Зависимости: express/qs/proxy-addr с известными уязвимостями (одна «критическая»: подмена IP через IPv4-mapped адрес) | Подмена IP ломала бы лимиты на вход | `npm audit fix`, теперь 0 уязвимостей в серверной части |
| Сессия жила 30 дней и после смены пароля | Украденный токен продолжал работать | В токен добавлен отпечаток пароля: после смены пароля все старые сессии закрываются |
| Лимит входа считался отдельно по каждой паре «адрес + логин» | Можно пробовать пароль по сотням логинов с одного адреса | Добавлен общий счётчик неудач на адрес (30 за 10 минут) |
| Вход с «объектом» вместо логина (`{"username": {...}}`) падал с ошибкой 500 | Лишний шум и ошибки, обход счётчика | Проверка типов во всех формах входа, регистрации и заявок |
| Время ответа на неверный логин отличалось от неверного пароля | Можно угадывать существующие логины | Для несуществующего логина выполняется такая же проверка хеша |
| Пароль без верхнего предела длины | Лишняя нагрузка на сервер | От 6 до 128 символов |
| Заявки без ограничений | Любой зарегистрированный клиент мог забить базу и Telegram | Длина полей, не больше 5 заявок и 10 обращений в поддержку в сутки |
| Нет защитных заголовков | Встраивание панели в чужую страницу, подсказки браузеру | `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`; убран `X-Powered-By` |
| Секрет JWT мог быть пустым или `change_me` | Токены можно было бы подделать | Панель не запускается со слабым секретом |
| Панель слушала все интерфейсы даже за Caddy | Доступ в обход HTTPS | Переменная `HOST`; `install.sh` с доменом ставит `127.0.0.1` |
| База и `.env` с обычными правами | Другие пользователи сервера могли прочитать ключи клиентов | Каталог данных 700, база, копии и `.env` 600 |
| Резервная копия делалась простым копированием файла | При работе базы в режиме WAL копия могла получиться неполной | Копия через встроенный механизм SQLite (`db.backup`) |
| Панель верила заголовку `X-Forwarded-For` от кого угодно (`trust proxy = 1`) | При доступе к панели напрямую (без домена и Caddy) атакующий подставлял случайный IP в каждом запросе и обходил все лимиты на перебор пароля | Верим только прокси на этой же машине (`trust proxy = loopback`); автотест подделывает заголовок с внешнего адреса |
| Редактирование сервера принимало любые значения полей (объекты, переводы строк) | Ошибки 500, мусор в командах и конфигах | Только короткие строки или числа без переводов строк |
| Ответ `awg genkey` с сервера подставлялся в команду без проверки | Скомпрометированный VPS мог вернуть вместо ключа произвольный текст | Принимается только ключ формата base64 |
| Порт Xray мог быть занят другой программой (например, 443 у Caddy) | Установка Xray молча не работала | Скрипт выбирает первый реально свободный порт или говорит, что порт занят |

## Проверено и признано безопасным

- Интерфейс: нет `dangerouslySetInnerHTML`, `eval`, хранения токенов в браузере (токен только в `httpOnly` cookie).

- Все маршруты, меняющие данные (`/api/servers`, `/api/peers` кроме чтения своих), требуют роль администратора; клиент видит только свои доступы (проверено тестом: чужие ссылки, QR, карточки возвращают 403).
- Токены с чужой подписью и с `alg=none` отклоняются.
- Команды на серверах: имена контейнеров, пути и SSH-параметры экранируются (`shellQuote`), сами команды передаются в base64; ключи клиентов генерирует панель.
- SQL везде через подготовленные запросы.
- SSH-пароль при создании ключа живёт только в памяти и не пишется в логи; ключи лежат в `data/ssh` (700/600) и не попадают в резервные копии.
- Приватный ключ REALITY панель не хранит (он остаётся в конфиге на сервере).
- CSRF: cookie `httpOnly` + `SameSite=Lax`, а API принимает только `application/json`.

## Осталось (риски, о которых нужно знать)

1. **Администратор панели = полный доступ к серверам.** Через панель можно выполнять команды на подключённых серверах (так она их настраивает). Пароль администратора делайте длинным, лучше вместе с защитой доменом и HTTPS.
2. **Панель работает от root** (нужно для docker). Если есть возможность, ограничьте доступ к ней по IP на уровне firewall.
3. **react-router (интерфейс), уязвимость средней степени**: открытый редирект и SSR-регидратация. Панель не использует ни то, ни другое (нет перехода по ссылкам из чужих данных и нет серверного рендеринга), поэтому на практике не эксплуатируется. Обновление до v7 потребует правок интерфейса, отложено.
4. **Hysteria2:** в ссылку добавлен `insecure=1` вместе с отпечатком сертификата (`pinSHA256`). Клиент, который не понимает отпечаток, но понимает `insecure`, согласится на любой сертификат. Проверьте это в вашем приложении (пункт чек-листа).
5. **SSH к серверам:** используется `StrictHostKeyChecking=accept-new`, то есть отпечаток сервера запоминается при первом подключении. Если при первой установке между панелью и сервером был злоумышленник, он мог бы подменить сервер.
6. **Открытая регистрация** (если не задан код приглашения и не включён Turnstile): любой может создать аккаунт клиента. Права у него минимальные (заявки), но лучше включить код приглашения или Turnstile.
7. **История репозитория** содержит удалённый файл `src/migrate-existing.js` с открытыми паролями клиентов (коммит `08320fd`). Смените эти пароли, репозиторий держите приватным; при желании историю можно переписать (`git filter-repo`).
8. В базе хранятся приватные ключи клиентов (иначе панель не смогла бы повторно выдать ссылку): храните резервные копии как секрет.
