# Обновление боевой панели (клиенты только на AmneziaWG 2.0)

Эта памятка для сервера, где панель уже работает. Ничего не удаляется: база клиентов остаётся, ссылки `vpn://`
у клиентов продолжают работать, переимпортировать ничего не нужно (это проверено автотестом на копии старой базы,
см. `tests/test-upgrade.sh`).

**Что изменится для людей:** все войдут в панель заново (старые сессии станут недействительными). Это нормально.

**Сколько времени:** 5–10 минут. Лучше делать, когда никто не добавляет клиентов.

## 0. Подготовка (1 минута)

Зайдите на сервер по SSH и найдите папку и имя сервиса панели:

```bash
systemctl list-units | grep skdsh          # имя сервиса, например skdsh-panel-skdsh-panel.service
systemctl cat <имя-сервиса> | grep WorkingDirectory   # папка панели, дальше она называется $PANEL
```

## 1. Резервная копия (обязательно)

```bash
cd $PANEL
STAMP=$(date +%F-%H%M)
mkdir -p ~/skdsh-backup-$STAMP
systemctl stop <имя-сервиса>                      # на секунду останавливаем, чтобы база была целой
cp -a data ~/skdsh-backup-$STAMP/data
cp -a .env ~/skdsh-backup-$STAMP/.env
git rev-parse HEAD > ~/skdsh-backup-$STAMP/old-commit.txt   # какая версия была (для отката)
systemctl start <имя-сервиса>
ls -la ~/skdsh-backup-$STAMP
```

Скачайте папку `~/skdsh-backup-…` себе на компьютер (например, `scp -r root@сервер:~/skdsh-backup-* .`).
VPN-контейнеры и ключи серверов не затрагиваются: панель их не пересоздаёт.

## 2. Обновление

```bash
cd $PANEL
git pull                      # если репозиторий приватный: git pull нужно делать с токеном или по SSH-ключу
npm install --omit=dev
cd frontend && npm install && npm run build && cd ..
```

Если на сервере нет git-репозитория, распакуйте присланный архив поверх папки, **не трогая** `data/` и `.env`
(`rsync -a --exclude data --exclude .env --exclude node_modules новая-папка/ $PANEL/`), и выполните две последние команды.

Проверьте `.env`: должен быть `JWT_SECRET` не короче 16 символов (у установки через `install.sh` он уже есть,
64 символа). Если панель стоит за Caddy (с доменом), добавьте в `.env` строку `HOST=127.0.0.1`: тогда панель
будет доступна только через HTTPS, а не напрямую по порту. Если открываете панель по IP и порту, строку не добавляйте.

## 3. Запуск и проверка

```bash
systemctl restart <имя-сервиса>
sleep 2
curl -s http://localhost:3001/api/health          # порт из .env (PORT), ответ: {"ok":true}
journalctl -u <имя-сервиса> -n 30 --no-pager      # не должно быть строк с ошибками
```

Откройте панель в браузере и убедитесь:
1. Вход работает (логин и пароль прежние).
2. Во вкладке «Серверы» ваш сервер с пометкой AmneziaWG 2.0.
3. Во вкладке «Доступы» все клиенты на месте, лимиты и блокировки такие же.
4. Откройте QR любого клиента: приложение AmneziaVPN его принимает, или у клиента, который уже подключён, VPN продолжает работать.
5. Создайте тестовый доступ и удалите его.

## 4. Откат (если что-то пошло не так)

```bash
cd $PANEL
systemctl stop <имя-сервиса>
git checkout $(cat ~/skdsh-backup-<метка>/old-commit.txt)     # вернуть прежний код
rm -rf data && cp -a ~/skdsh-backup-<метка>/data data         # вернуть прежнюю базу
cp ~/skdsh-backup-<метка>/.env .env
cd frontend && npm run build && cd ..
systemctl start <имя-сервиса>
```

Клиенты при этом не пострадают в любом случае: их VPN работает независимо от панели.

## Напоминания

- Если репозиторий делаете приватным: на сервере `git pull` потом работает только с токеном доступа или SSH-ключом.
- Файл `src/migrate-existing.js` когда-то лежал в репозитории с открытыми паролями клиентов. Из текущего кода он удалён,
  но остался в истории (коммит `08320fd`). Смените пароли тех клиентов (или считайте их скомпрометированными), а репозиторий
  держите приватным.
