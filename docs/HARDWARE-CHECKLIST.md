# Чек-лист проверки на настоящем железе

Здесь только то, что нельзя проверить без настоящего VPS и телефона. Всё остальное закрыто автотестами (`tests/run-all.sh`).
Отмечайте пункты по порядку. Если пункт не прошёл, запишите, что именно вы видели (текст ошибки или скриншот), и пришлите.

Тесты можно делать на **одном IP-адресе**: протоколы занимают разные порты, панель сама выбирает свободный.
Лучше брать чистый VPS без Caddy/nginx на порту 443; если порт занят, панель возьмёт 8443 и скажет об этом в журнале.

## A. Быстрая проверка за 5 минут (после установки или обновления)

1. [ ] `curl http://localhost:ПОРТ/api/health` на сервере отвечает `{"ok":true}`.
2. [ ] Вход в панель в браузере, вкладки открываются, ошибок нет.
3. [ ] Вкладка «Серверы»: сервер есть, в журнале установки нет красных строк.
4. [ ] Создайте тестовый доступ, откройте «QR»: QR показывается, ссылка копируется.
5. [ ] Телефон: импортируйте доступ, включите VPN, откройте `https://2ip.ru` или `https://ifconfig.me`: показывается IP **сервера**, а не ваш.
6. [ ] В панели у доступа появился трафик и статус «онлайн» (подождите 1–2 минуты).
7. [ ] Нажмите «Заблокировать»: через несколько секунд интернет через VPN пропадает; «Разблокировать»: возвращается.
8. [ ] Удалите тестовый доступ.

## B. Установка серверов (по одному протоколу на шаг)

Для каждого протокола: вкладка «Серверы» → «Добавить сервер» → «Создать новый» → «На этой машине» (или SSH).

### B1. AmneziaWG 2.0
1. [ ] Установка проходит до «Сервер добавлен в панель», предупреждений нет (или понятны).
2. [ ] `docker ps` на сервере показывает контейнер; `ss -lun | grep 39001` (порт из панели): слушает UDP.
3. [ ] Создайте доступ и импортируйте в приложение **AmneziaVPN** (по QR или ссылке «Открыть в приложении»).
4. [ ] Подключение устанавливается, сайты открываются, IP сервера (см. A5).
5. [ ] Рядом создайте второй доступ на втором телефоне/ПК: оба работают одновременно.

### B2. AmneziaWG 3.1 (если нужен)
1. [ ] Те же шаги. **Важно:** приложение AmneziaVPN должно быть свежей версии с поддержкой 3.1. В коде для 3.1 есть предположение о формате `vpn://` (поле версии протокола): если приложение не принимает ссылку, пришлите текст ошибки.
2. [ ] Импорт через файл `.conf` (кнопка «Скачать конфиг»/скопировать конфиг) тоже работает.

### B3. VLESS + REALITY
1. [ ] Установка: в журнале «Xray скачан и проверен», порт TCP (обычно 443; если занят, будет 8443).
2. [ ] Если у хостера есть свой firewall: порт TCP открыт и там.
3. [ ] Приложение **Happ** (iOS/Android): «+» → вставка из буфера → профиль добавился.
4. [ ] Подключение работает, 2ip.ru показывает IP сервера.
5. [ ] Те же ссылки в **v2rayNG** (Android) или **v2rayN** (Windows): работают.
6. [ ] Блокировка доступа отключает клиента сразу, без обрыва остальных (держите второго клиента, качающего файл).

### B4. Hysteria2
1. [ ] Установка: порт **UDP** (обычно 443); открыт в firewall сервера и у хостера **как UDP**.
2. [ ] Импорт ссылки `hysteria2://` в Happ или Hiddify: профиль добавляется без ошибок.
3. [ ] Подключение работает. Если приложение пишет про сертификат: запишите текст (ссылка содержит отпечаток `pinSHA256` и `insecure=1`).
4. [ ] **Проверка безопасности отпечатка:** в панели создайте второй Hysteria2-сервер на том же IP, возьмите ссылку первого сервера, поменяйте в ней порт на порт второго. Если приложение подключилось, оно не проверяет отпечаток (тогда используйте VLESS REALITY там, где важна защита от подмены).
5. [ ] В мобильной сети (не Wi-Fi) работает; если нет, UDP режется оператором, это нормально для части сетей.
6. [ ] Добавление нового клиента вызывает короткий перезапуск (около секунды): у уже подключённых клиентов соединение восстанавливается само.

### B5. Shadowsocks-2022
1. [ ] Установка: порт TCP и UDP открыт.
2. [ ] Импорт ссылки `ss://` в Happ / v2rayNG / Shadowrocket: профиль добавляется. Если приложение не принимает ссылку, запишите название и версию приложения (метод `2022-blake3-aes-128-gcm` поддерживают не все старые версии).
3. [ ] Подключение работает, 2ip.ru показывает IP сервера.
4. [ ] Добавление клиента кратко перезапускает сервер (около секунды).

### B6. Все протоколы вместе на одном IP
1. [ ] Создайте по серверу каждого типа на одной машине: у каждого свой порт, ни один не мешает другому.
2. [ ] `docker ps`: контейнеры живы; `ss -ltun`: нужные порты слушаются.
3. [ ] Перезагрузите VPS: после загрузки все контейнеры поднялись сами (`--restart always`) и панель тоже.

## C. Функции панели

1. [ ] **Лимит трафика:** выдайте доступ с лимитом 1 ГБ, скачайте файл больше: доступ сам блокируется (проверка раз в минуту), в панели статус «заблокирован».
2. [ ] **Сброс лимита в начале месяца** срабатывает 1-го числа в 00:00 сервера (проверен автотестом); вручную его проверять не нужно, но 2-го числа убедитесь, что заблокированные за лимит доступы снова работают.
3. [ ] **Заявка клиента:** зарегистрируйтесь вторым аккаунтом, отправьте заявку: приходит уведомление в Telegram (если настроено), админ видит заявку.
4. [ ] **Клиентский вход:** клиент видит только свои доступы и инструкцию «Как подключиться» для своего протокола.
5. [ ] **Телефон:** откройте панель на телефоне (портретный режим): окна не обрезаются, кнопки нажимаются, QR виден целиком.
6. [ ] **Telegram:** бот присылает уведомление о заявке.
7. [ ] **Резервные копии:** на сервере в `data/backups/` есть файл за сегодня; `sqlite3 data/backups/panel-ДАТА.db "select count(*) from peers"` показывает число доступов.
8. [ ] **Установка по SSH на другой сервер** (если пользуетесь): режим «Другой сервер (SSH)», вход по паролю (создаётся ключ) и по готовому ключу; после установки пароль нигде не остаётся (`grep -r ваш_пароль /opt /root /var/log` ничего не находит).
9. [ ] **Установка из `install.sh`** на чистой машине: режим «всё на одном сервере», затем с доменом и HTTPS (A-запись домена на IP машины).
10. [ ] **Смена пароля:** после смены на втором устройстве просит войти заново.

## D. Безопасность на реальном сервере

1. [ ] `ls -la ПАПКА_ПАНЕЛИ/data ПАПКА_ПАНЕЛИ/.env`: каталог `data` права `drwx------`, `.env` и `panel.db` права `-rw-------`.
2. [ ] С домена и Caddy: `curl -I http://IP:3001` снаружи не отвечает (панель слушает только 127.0.0.1), а `https://домен` отвечает.
3. [ ] `curl -sI https://домен | grep -i "x-frame-options\|x-content-type"`: заголовки есть.
4. [ ] Перебор пароля: 5 неверных попыток подряд блокируют вход на 15 минут.
5. [ ] `ufw status` (или панель хостера): открыты только нужные порты (SSH, 80/443 если домен, порты VPN). Порт панели 3001 наружу не нужен, если есть домен.
6. [ ] Файл `data/ssh/` (если создавали ключи паролем): права 700 и 600.

## E. Обновление боевой панели

Сделайте по `docs/UPGRADE.md`, затем пройдите раздел A и пункты 1–4 из раздела C.
